# Zenn記事 設計仕様書

## 概要

Claude Code + Superpowersを使ってTODOアプリを作った体験をZennに投稿する記事。Claude Codeユーザーに向けて、Superpowersの価値を伝える。

## 記事メタ情報

- **想定読者**: Claude Codeは使っているが、Superpowersを知らない/使っていない人
- **トーン**: 体験レポート + 読者が試すためのポイントも押さえる（中間型）
- **技術詳細**: 最小限（Superpowersの体験にフォーカス）
- **長さ**: 5〜10分で読める中程度
- **構成**: 「プロンプト → 完成品」ビフォーアフター型

## Zenn公開メタデータ

- **タグ**: `claudecode`, `superpowers`, `ai`, `python`
- **記事タイプ**: tech
- **サムネイル**: image.png（デザイン3案の比較画面）

## 使用素材

- `docs/screenshots/image.png` — brainstormのビジュアルコンパニオンでデザイン3案を提示している画面
- `docs/screenshots/作業中.png` — 完成したTODOアプリの画面

## 記事構成

### セクション1: 冒頭（フック）

**タイトル案**: 「Claude Codeに"Superpowers"を入れたら、プロンプト1行からTODOアプリが完成した」

冒頭で以下を並べる:

- 投げたプロンプト（コードブロック）:

```
TODOアプリを作りたい。superpowersの使い方を学ぶチュートリアル的に作ってみたい。
その内容をZennの記事にしたいから、そこそこ見栄えがいいやつで。
ただし実装はシンプルに。pythonのfastapiを使って。フロントエンドはお任せで。
```

- 完成品のスクリーンショット（作業中.png）
- 「このアプリは、上のプロンプトから始まって、Claudeの質問に答えていくだけで完成した」という一文で引き込む

### セクション2: Superpowersとは

短めの導入（3〜5行）:

- Claude Codeの拡張プラグインであること
- brainstorm → plan → 実装 → code-review というワークフローを提供すること
- 「AIに丸投げ」ではなく「AIと対話しながら設計→実装する」ツールであること
- インストール方法に軽く触れる（1行コマンド程度）

### セクション3: brainstorm — 質問に答えるだけで設計が固まる

記事の中心パート。3つのサブセクションで構成。

#### 3-1. プロンプトと仕様書の比較

最初のプロンプトで指定したこと／指定しなかったことを表で整理:

| 項目 | プロンプトで言ったこと | 仕様書で決まったこと |
|------|----------------------|---------------------|
| Backend | FastAPI | FastAPI + SQLAlchemy + SQLite |
| Frontend | 「お任せ」 | HTMX + Jinja2（Node.js不要） |
| デザイン | 「見栄えがいい」 | ミニマル・モノトーン（Notion風） |
| 構成 | 「シンプルに」 | main.py 1ファイルに集約 |
| 機能 | 言及なし | CRUD + フィルター + インライン編集 |
| テスト | 言及なし | pytest + in-memory SQLite |

→ 「お任せ」「シンプルに」という曖昧な指示が、具体的な技術選定と設計に変換されている

#### 3-2. brainstormとの問答の流れ

仕様書から逆算した、brainstormとのおおよその問答。記事では「おおよそこのような問答があった」と明示し、再現ではなく体験の要約として提示する:

1. 「フロントエンドの技術はどうしますか？」→ React/Vue等ではなくHTMX + Jinja2が提案された（npm不要でシンプル）
2. 「TODOアプリの機能スコープは？」→ 追加・完了・削除・編集・フィルターに絞られた
3. 「ビジュアルコンパニオンを使いますか？」→ ブラウザで3つのデザイン案を比較（**image.pngを挿入**）
4. 「プロジェクト構成はどうしますか？」→ チュートリアル用にシングルファイル構成が選ばれた
5. 「テストは含めますか？」→ in-memory SQLiteでAPIテスト

#### 3-3. 他サービスとの違い: 質問の「質」

- 多くのAIツールはプロンプトを受けたら即座にコードを生成する
- Superpowersのbrainstormはまず理解しようとする — 一度に1つずつ質問してくれる
- 質問は選択肢形式で提示され、各選択肢に対して:
  - おすすめはどれかが明示される
  - その選択がプロジェクトにどう影響するか（メリット・デメリット）が説明される
- 記事中にbrainstormの質問フォーマットの具体例を掲載し、読者が質問の質を実感できるようにする（例: フロントエンド選定の質問で「A. React — リッチなUIが作れるがnpmセットアップが必要」「B. HTMX + Jinja2（推奨）— npm不要でシンプル、チュートリアル向き」のような形式）
- 技術的な判断に自信がなくても、影響範囲を理解した上で選べる
- 結果として「AIが勝手に決めた」ではなく「自分で選んだ」という納得感のある設計が出来上がる

### セクション4: plan → 実装 → code-review

brainstorm以降のワークフローを軽めに紹介:

- **plan**: brainstormで固まった設計から、実装ステップの計画を自動生成。何をどの順番で作るかが整理される
- **実装**: 計画に沿ってClaude Codeがコードを書く。各ステップ完了時にcode-reviewerが自動レビュー
- **code-review**: 実装が計画通りか、品質に問題ないかをチェック。人間のコードレビューと同じ感覚

→ brainstormで「何を作るか」を決め、planで「どう作るか」を決め、実装中もreviewで品質を担保する。一貫したワークフローが自動的に回ることがSuperpowersの本質。

### セクション5: 完成品とまとめ

- 完成したTODOアプリのスクリーンショット（作業中.png）を再掲
- 最初のプロンプトで「見栄えがいいやつで」と言った通り、イメージ通りのものが出来上がった
- Superpowersは「AIに丸投げ」ではなく「AIと一緒に設計する」体験
- 質問に答えていくだけで、自分の意思が反映された成果物が出来上がる
- Claude Codeを既に使っている人なら、すぐに導入できる
- インストール方法・参考リンクを末尾に添える
